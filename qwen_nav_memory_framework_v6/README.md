# qwen-nav-memory-framework v0.6

Relative-pose topo-metric episodic memory framework for a Qwen3-VL semantic navigation supervisor.

The framework keeps the original `nav_vlm_waypoint_v1` envelope:

```text
RGB observation + robot state + coarse goal + memory
    -> Qwen3-VL semantic supervisor
    -> go / rotate / stop / request_observation
    -> backend validation + fast local controller
    -> verified memory update
    -> repeat
```

The VLM is the slow semantic supervisor. It does not drive motors directly. It either selects a visible local fine waypoint for the fast S2E/PixelNav-style module or requests rotation / additional observation when the current view is insufficient.

## What v0.6 adds over v0.5

v0.6 keeps the v0.5 spatial memory design and adds **GaP-lite** safety instrumentation. This is not a full Graph-as-Policy interpreter. It is a small validation sidecar that makes the VLM decision loop more typed, auditable, and conservative.

```text
GaP-lite candidate references
  memory.candidate_refs.exits[*].candidate_ref is generated by the backend
  action=go must select selected_candidate_ref from those refs
  unknown refs, missing refs, or avoid=true refs are recovered with request_observation
  VLM no longer needs to invent or copy raw edge ids for action selection

GaP-lite memory-op references
  confirm_revisit_node / request_merge_nodes should use candidate_ref from memory.candidate_refs.revisits
  backend resolves candidate_ref to node_id only if spatial_plausibility.accepted=true
  spatially implausible same-place memory ops are dropped before topology mutation

Validation checkpoints
  every step records validation_checkpoints and validation_feedback
  stable rule ids such as NAV_GO_001, NAV_GO_003, NAV_MEM_004 identify failures
  save_run() writes Feedback.md for offline analysis and prompt/threshold tuning

Nav skill cards
  memory.nav_skill_cards describes when go, request_observation, confirm_revisit_node, and rotate-to-front are allowed
  Qwen sees the rule cards in the memory context
  backend still enforces the rules; prompt compliance alone is not trusted
```

The core v0.5 memory features remain unchanged:

```text
VLM-grounded place recognition with soft merge
Spatial plausibility gate for revisit / merge
Live latest-node-to-current-robot relative pose relation
Rotate-to-front fine-goal policy
Directional deadlock state machine
ObjNav object-belief hook
Pose graph optimization intentionally TODO / disabled
```

## Real robot / Habitat integration

Implement this protocol:

```python
class MyBackend:
    def get_robot_state(self) -> RobotState:
        ...

    def get_observation(self) -> Observation:
        ...

    def execute_waypoint(self, *, view_type: str, view_id: int, point_px: tuple[int, int], ttl_ms: int) -> ActionOutcome:
        ...

    def rotate(self, yaw_deg: float) -> ActionOutcome:
        ...

    def capture_views(self, yaw_offsets_deg: Sequence[float], mode: str = "directed_sweep") -> Observation:
        ...
```

`execute_waypoint` should call your S2E/PixelNav-style module. It must return collision/progress/odometry information. Without action outcome and odometry, Qwen can still choose actions, but the framework cannot robustly form relative-pose edges or confirm deadlocks.

## Latest-node live pose relation

The graph still does not store global node poses. The agent keeps a transient robot-state anchor for the current/latest node and exposes this runtime relation in memory:

```json
"current_pose_relation_to_latest_node": {
  "pose_type": "live_relative_SE2_not_global_node_pose",
  "latest_node_to_robot": {"dx_m": 0.65, "dy_m": 0.0, "dyaw_deg": 0.0},
  "robot_to_latest_node": {"dx_m": -0.65, "dy_m": 0.0, "dyaw_deg": 0.0}
}
```

This floating transform lets the backend convert `edge.relative_pose_src_to_dst` from the latest node frame into the current robot frame before Qwen chooses a view or fine goal. When a new node is later committed, the temporal edge uses the cumulative latest-node-to-robot pose.

## GaP-lite VLM context

The top-level input remains `nav_vlm_waypoint_v1`, but `memory` is upgraded to `nav_memory_context_v6`.

```json
{
  "schema_version": "nav_memory_context_v6",
  "policy_harness_state": {
    "schema_version": "nav_policy_harness_lite_v1",
    "policy_graph_mode": "GaP-lite_static_sidecar_not_full_interpreter",
    "current_stage": "normal_goal_seek | verify_revisit | escape_deadlock",
    "requirements": {
      "go_requires_selected_candidate_ref": true,
      "revisit_memory_ops_require_candidate_ref": true,
      "false_positive_merge_policy": "keep_duplicate_node_when_uncertain"
    }
  },
  "candidate_refs": {
    "exits": [
      {
        "candidate_ref": "exit_001",
        "candidate_type": "candidate_exit",
        "edge_id": "e_00012",
        "view_type_hint": "front",
        "bearing_deg_robot": 0.0,
        "status": "unknown_frontier",
        "avoid": false
      }
    ],
    "revisits": [
      {
        "candidate_ref": "revisit_001",
        "candidate_type": "revisit_candidate",
        "node_id": "n_00007",
        "spatial_plausibility": {
          "accepted": true,
          "reason": "within_baseline"
        }
      }
    ]
  },
  "nav_skill_cards": {
    "go_front_fine_goal": {"type": "action"},
    "confirm_revisit_node": {"type": "memory_op"}
  }
}
```

For `action=go`, Qwen should output:

```json
{
  "action": "go",
  "selected_candidate_ref": "exit_001",
  "selected_view_type": "front",
  "selected_image_point": [320, 360],
  "fine_goal": {
    "valid": true,
    "point_px": [320, 360],
    "navigability": "likely_free"
  }
}
```

For place recognition, Qwen should output memory ops with revisit candidate refs:

```json
{
  "memory_ops": [
    {
      "op": "confirm_revisit_node",
      "candidate_ref": "revisit_001",
      "confidence": 0.86,
      "reason": "same doorway/corner layout and spatial gate accepted"
    }
  ]
}
```

The backend resolves `candidate_ref` to node/edge ids and rejects unsafe refs. The VLM is never trusted to commit topology-changing memory mutations by itself.

## Validation rule ids

Important checkpoint rules:

```text
NAV_GO_001  go requires selected_candidate_ref
NAV_GO_002  selected_candidate_ref must exist in memory.candidate_refs.exits
NAV_GO_003  selected exit candidate must not have avoid=true
NAV_GO_004  selected_view_type must match the candidate view_type_hint
NAV_GO_005  front-only fast-module policy annotation
NAV_GO_006  backend negative-branch guard blocked unsafe go
NAV_MEM_002 revisit/merge memory op requires candidate_ref
NAV_MEM_003 revisit candidate_ref must exist
NAV_MEM_004 same-place memory op requires spatial_plausibility.accepted=true
NAV_MEM_005 memory op candidate_ref resolved successfully
NAV_POLICY_001 GaP-lite validation sidecar completed
```

Invalid `go` references recover to `request_observation.directed_sweep`. Invalid same-place memory ops are dropped and duplicate nodes are kept.

## Minimal PointNav code

```python
from nav_memory_qwen import (
    NavMemoryAgent, NavAgentConfig,
    StaticImageBackend, OpenAICompatibleVLMClient,
)

robot = StaticImageBackend("front_rgb.jpg", start_xy=(0.0, 0.0), start_heading_rad=0.0)
vlm = OpenAICompatibleVLMClient.from_env()
agent = NavMemoryAgent(
    robot=robot,
    vlm_client=vlm,
    config=NavAgentConfig(
        max_steps=50,
        force_front_view_waypoint=True,
        vlm_confirms_place_recognition=True,
        gap_lite_enabled=True,
        require_candidate_ref_for_go=True,
        require_candidate_ref_for_revisit_ops=True,
    ),
)

result = agent.run_until_done(goal_map_xy=(6.418, 21.904))
agent.save_run("runs/episode_001")
print(result.summary())
```

result = agent.run_until_done(target_object="mug", max_steps=50)

ObjNav is implemented as a memory and prompt hook. Production use should connect object detection, open-vocabulary detection, or Qwen object evidence to `memory_ops` such as `update_object_belief` or `mark_object_seen`.

## Why pose graph optimization is not included

This version keeps relative-pose edges, supports directed path composition, and adds `relative_pose_between_nodes()` for arbitrary connected node pairs using chain-rule composition and inverse-edge traversal. It does not solve global consistency after loop closure. `MemoryGraph.optimize_pose_graph()` is an explicit TODO hook and raises `NotImplementedError` if called. This keeps the current version centered on VLM-prompted reasoning, verified memory writes, directional negative memory, and GaP-lite runtime validation rather than algorithmic SLAM optimization.
